# Business and Menu

The business and menu module is Sprint 1 core product work.

## Business Flow

1. Owner signs in with Clerk.
2. App calls `GET /me` to sync the user and read onboarding status.
3. If onboarding returns `CREATE_BUSINESS`, owner creates a business.
4. API creates the `Business` and an active `BusinessUser` with role `OWNER`.
5. `POST /businesses` returns the created business, current owner membership,
   and app context so Flutter can continue.
6. Owner or manager creates categories and menu items.
7. Flutter can load `GET /businesses/:id/app-context` for business context,
   current membership, role permissions, and public menu link data.
8. Flutter/Admin-Web can load `GET /businesses/:id/dashboard-summary` for
   counts, permissions, public menu URL data, and deterministic owner workflow
   hints.
9. Staff can view limited business information, dashboard summary, and the public link, but cannot
   edit the menu or manage members.
10. Customer scans a QR code generated by the client and sees the public menu
   website.

## Onboarding Status

`GET /me` is the first authenticated startup endpoint. It returns the synced
user, active memberships, and an onboarding decision:

- `CREATE_BUSINESS`: the user has zero active businesses.
- `OPEN_DASHBOARD`: the user has one active business.
- `SELECT_BUSINESS`: the user has more than one active business.

Inactive memberships are not returned by default from `/me`.

## Business Roles

- Owner: manages business settings, menu, members, public link, and billing.
- Manager: manages menu and can view members and public link, but cannot manage
  business settings or members.
- Staff: can view app context and public link only.

Staff cannot edit menu items or categories.

The backend permission payload uses these booleans:

- `canManageBusiness`: owner only.
- `canManageMenu`: owner or manager.
- `canManageMembers`: owner only.
- `canViewMembers`: owner or manager.
- `canViewPublicLink`: owner, manager, or staff.

Member update and delete routes protect the last active owner. The API rejects
any demotion, deactivation, or soft delete that would leave the business with no
active owner.

Owner workflow endpoint access:

- Dashboard summary: owner, manager, and staff active members.
- Menu reorder: owner and manager only.
- Business settings: owner only.
- Members list: owner and manager only.
- Member create/update/delete: owner only.

## Public Menu Link

The business app can call `GET /businesses/:id/public-link` to get:

- `publicMenuPath`, such as `/m/tavrix-cafe`.
- `publicMenuUrl`, such as `http://localhost:3001/m/tavrix-cafe`.
- `qrPayload`, which is the same URL string.

The backend does not generate QR images in Sprint 2. Flutter should generate the
QR image locally from `qrPayload`. `CUSTOMER_WEB_BASE_URL` controls the URL base
and defaults to `http://localhost:3001` for local development.

`GET /businesses/:id/dashboard-summary` also returns `publicMenu.path`,
`publicMenu.url`, and `publicMenu.qrPayload`. The QR payload remains the public
URL string; the backend does not add a QR image dependency.

## Dashboard Summary

`GET /businesses/:id/dashboard-summary` supports the owner workflow for
Flutter/Admin-Web. It returns:

- Business profile fields.
- Current user's role and permission booleans.
- Counts for active/inactive categories, available/unavailable items, and active
  members.
- Public menu path, URL, and QR payload.
- Onboarding hints.

Recommended next steps are deterministic:

- `ADD_CATEGORY`: no active categories.
- `ADD_ITEM`: active categories exist but no available item under an active
  category exists.
- `SHARE_PUBLIC_MENU`: active categories, public items, and a public URL exist.
- `READY`: fallback when no setup action is recommended.

The endpoint checks active business membership and does not allow
cross-business access.

## Business Fields

- `name`: public display name.
- `slug`: public URL identifier.
- `type`: initial values are restaurant or cafe, but the platform is more general.
- `logoUrl`: optional business logo.
- `coverUrl`: optional cover image.
- `currency`: default `IQD`.
- `language`: default `ar`.
- `city`: optional city.
- `status`: `ACTIVE`, `SUSPENDED`, or `PENDING`.

`PATCH /businesses/:id` remains owner-only. Supported editable profile fields
are `name`, `type`, `city`, `currency`, `language`, `logoUrl`, and `coverUrl`.
Subscription/payment fields, custom domains, QR images, and uploads are not part
of this settings contract.

## Menu Categories

- Categories belong to one business.
- Categories are sorted by `sortOrder`.
- Business management lists return only categories where `isActive = true` by
  default.
- Business management lists can pass `includeInactive=true` to include archived
  categories.
- Public menu shows only categories where `isActive = true`.
- Arabic name is required.
- English name is optional.
- Sprint 1 delete archives categories by setting `isActive = false`.
- Restore an archived category with `PATCH /categories/:id` and
  `{ "isActive": true }`.
- Reorder categories with `PATCH /businesses/:id/categories/reorder`.
- Reorder supports active and inactive categories.
- Reorder rejects duplicate IDs, IDs from another business, and invalid
  `sortOrder` values.

## Menu Items

- Items belong to one business and one category.
- Items are sorted by `sortOrder`.
- Business management lists return only items where `isAvailable = true` by
  default.
- Business management lists can pass `includeInactive=true` to include
  unavailable or archived items.
- Public menu shows only items where `isAvailable = true`.
- Price is stored as a Decimal in the database.
- `imageUrl` is optional.
- Arabic name is required.
- English name and descriptions are optional.
- Sprint 1 delete archives items by setting `isAvailable = false`.
- Restore an archived/unavailable item with `PATCH /items/:id` and
  `{ "isAvailable": true }`.
- Reorder items with `PATCH /businesses/:id/items/reorder`.
- Item reorder is implemented because `MenuItem.sortOrder` exists in the current
  Prisma schema.
- Reorder supports available and unavailable items.
- Reorder rejects duplicate IDs, IDs from another business, and invalid
  `sortOrder` values.

## Demo Seed

The seed creates or updates the demo business:

- Business: Tavrix Cafe
- Owner user: `user_tavrix_owner`, `owner@tavrix.local`, `Tavrix Owner`
- Owner membership: active `OWNER`
- Categories: Hot Drinks, Desserts
- Items: Turkish Coffee, Tamriya, Baklava

The public mock route can then be replaced with real API data from `GET /public/m/tavrix-cafe`.

Local development auth header for the owner:

```text
Authorization: Bearer dev:user_tavrix_owner;email=owner@tavrix.local;name=Tavrix%20Owner
```
